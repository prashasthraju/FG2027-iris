# Who Is Driving the Avatar? Code and result files

Anonymous code release for the FG2027 submission *Who Is Driving the Avatar? Cancelable-Domain Driver Verification for Talking-Head Reenactment with Revocable Proxy Irises and
Decentralized Identity*. It lets a reviewer (1) check the protocol rules, (2) recompute the headline numbers independently from released score files, (3) see which code produced
every number in the paper, and (4) re-run the full pipeline if they hold the datasets and a GPU.

**What is not here.** The datasets (RAVDESS, CASIA-Iris-Distance, UTIRIS, AVAPrintDB), generated videos, face or iris images, iris templates and embeddings, the issuer's private registry,
and the model weights (LivePortrait, ArcIris, ...) are licensed and are not redistributed; see `DATA.md` and `THIRD_PARTY.md`. The result files in `outputs/` hold only scalar scores,
verdicts and counts.

## Quick start (about 10 seconds, CPU only, no data)

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements-min.txt
bash reproduce/run_tier01.sh
```

## Three levels of reproduction

| Tier | What it checks | Needs | Command |
|---|---|---|---|
| 0. Protocol rules | commit and open with a salt (wrong template or salt rejected, a bare hash is not the commitment); only the issuer writes; a record needs a valid issuer proof and driver countersignature; a tampered record, a commitment differing from the DID version, a forged source binding and a version revoked in an earlier block are all rejected; the chain detects a rewritten block | nothing (synthetic data) | `python tests/test_protocol.py` |
| 1. Headline numbers | T1, EER, AUC, TAR at 1% FAR, rank-1, the distance-only acceptance, the verdict counts, the false-claim and un-embedded-copy counts, recomputed from per-session scalar scores and verdicts *without importing the evaluation code*, then compared with the macros the paper prints; and `paper_gen/` (every macro and table body) regenerated byte-identically from `outputs/` | nothing (shipped score files) | `python reproduce/recompute_metrics.py`, `bash reproduce/regenerate_paper_numbers.sh` |
| 2. Full pipeline | enrolment, generation with the hook, verification, the other generators, the baselines and the carrier and resolution studies | the datasets in `DATA.md`, the model weights, one 8 GB GPU, days of compute | see "Full pipeline" below |

Tier 2 was run end to end for the paper. After the machine-specific paths were replaced by environment variables for this release it was only compile-checked, not
re-run, so expect to set `PERSONALIVE_DIR`, `PERSONALIVE_PYTHON`, `EMBED_WORKER_PYTHON` and the `third_party/` folders as described in `DATA.md`.

## Things a careful reader should know

* **The pool is a stand-in.** The 79-entry UTIRIS pool replaces the cancelable transform of the person's own iris (the main design, not part of this release). The one-time
  per-session proxy of the paper is a design property; `tools/` implements one proxy per person and epoch.
* **The ledger is simulated** (`tools/proxy_ledger.py`: one process, a JSON file, secp256k1 signatures, a hash-chained block list); real irises are simulated by pairing each person with a CASIA subject.
* **Ledger migration.** The first sessions were recorded when DID versions still carried proxy codes. `tools/proxy_commit_migrate.py` replaced every code by a salted keccak-256
  commitment, moved templates and salts to the issuer's private registry (not released, because the templates are embeddings of licensed UTIRIS irises) and re-signed the records;
  video hashes, session ids and block order are unchanged. All reported results come from verification re-run on the migrated ledger.
* **T1.** It was frozen on the 15 tuning sessions, against the proxies enrolled at that time, before the test sessions were generated. `reproduce/recompute_metrics.py` reproduces it.
* **Legacy code.** `cancelable/platform.py`, `cancelable/identify.py`, `cancelable/ledger.py`, `tools/transfer_eval*.py` and the 1:N functions of `tools/proxy_verify.py` (`verify_video`, `decide`)
  belong to earlier designs (public proxy codes, 1:N identification of the proxy in the video, an Anvil chain); the paper's verifier is `tools/proxy_issuer_eval.py` (`verify_session`).
* **Comments** mention identifiers such as `D13` or `batch 4`: they point to an internal decision log that is not released; "batch 4" is the large 67-person session.
* **Not measured:** removal and forgery attacks on either carrier, a human study of the visible iris change, a social-platform re-encode.

## Full pipeline (Tier 2)

Order of the original run; each script has a docstring with its options. Put the data and weights where `DATA.md` says.

```bash
python tools/ravdess_prep.py                          # RAVDESS sources and driving clips
python tools/proxy_attr.py plan                       # seeded people, enrolment, tuning split (commit the plan before generating)
python tools/proxy_attr.py gen                        # LivePortrait with the driver's proxy embedded inline, PDQ hashes, signed records
python tools/ravdess_more_drivers.py && python tools/proxy_batch4.py   # the large session (67 people)
python tools/proxy_gen_parallel.py gen --shard 0 --of 3 && python tools/proxy_gen_parallel.py record
python tools/proxy_verify.py extract && python tools/proxy_verify.py variants   # iris observations; CRF 23/30, blur, edit variants
python tools/proxy_verify.py calibrate                # T1 on the tuning sessions
python tools/proxy_commit_migrate.py                  # public-proxy ledger -> salted commitments (writes the private registry)
python tools/proxy_issuer_eval.py setup && python tools/proxy_issuer_eval.py evaluate
python tools/proxy_paper_numbers.py && python tools/proxy_referee_numbers.py
python tools/export_scores.py                         # per-session scalar scores used by Tier 1
python tools/paper_numbers.py                         # paper_gen/numbers.tex and tab_*.tex
```

Other generators and studies: `tools/gen_liax.py`, `tools/gen_edtalk.py`, `tools/personalive_lowmem.py`; `tools/behav_*.py`, `tools/behavioural_on_sessions.py` and
`tools/baseline_behavioural.py` (behavioural baselines); `tools/wm_study.py` (watermark carrier); `tools/resolution_sweep.py`; `tools/appearance_change.py`.
`docs/CODE_MAP.md` maps the paper's equations and protocol steps to functions.

## Layout

```
iris_pipeline/   iris detection, segmentation, rubber-sheet strips, the layered compositor, visibility gate, ArcIris wrapper
cancelable/      pool of proxy irises (pool.py) and the model-agnostic per-frame embedder (inline.py); the rest is legacy
tools/           protocol (proxy_ledger.py, proxy_verify.py, proxy_issuer_eval.py), experiments, baselines, number generation
tests/           Tier 0 protocol tests
reproduce/       Tier 1 scripts
outputs/         scalar result files (JSON) with provenance
paper_gen/       the macros and table bodies the paper prints (generated)
```
